Single-region resilience

Multi-AZ / Stretch Cluster

Use when: RTO/RPO greater than zero is acceptable and the proposed locations are connected within the flow’s 50 ms screening threshold.

Prerequisites

  • Locations within 50 ms for initial screening; typical Multi-AZ designs should target stable ≤5 ms latency.
  • Rack-aware broker and KRaft controller placement.
  • Replication factor, min ISR, and capacity sized for one location loss.
  • Measured bandwidth, jitter, and p99 latency between locations.

Trade-offs

Cross-AZ network cost and synchronous replication latency increase, but the design does not protect against a whole-region outage.

Regional resilience

Multi-Region Clusters (MRC)

Use when: One logical cluster must target zero RPO and near-zero RTO through a regional outage.

Prerequisites

  • A validated 2.5/3-location topology with stable ≤50 ms connectivity.
  • Confluent Server rack awareness and explicit replica placement.
  • Correct KRaft quorum, observer promotion, acks, and min ISR design.
  • Surviving-region capacity and tested client/application failover.

Trade-offs

Highest network and operational cost; synchronous replicas may add producer latency, while observers trade RPO for lower latency.

Independent regional clusters

Cluster Linking

Use when: Non-zero RPO/RTO is acceptable and latency is above the stretch-cluster threshold, requiring independent clusters.

Prerequisites

  • Reachable source and destination clusters with replication bandwidth.
  • Supported Confluent Platform versions and Cluster Linking enabled.
  • Required ACLs/RBAC, topic filters, and consumer-offset synchronization.
  • Monitored mirror lag plus tested failover, failback, and promotion runbooks.

Trade-offs

Cross-cluster replication is asynchronous, so RPO is greater than zero. Active-active also requires conflict-free application ownership.
